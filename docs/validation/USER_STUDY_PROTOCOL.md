# Structured user-study protocol

This protocol measures whether intended users can complete the workflow; it does not measure model accuracy, adoption, or real-world impact.

## Study definition

- Intended participant profile and recruitment method.
- Consent, privacy, recording, withdrawal, and data-retention procedure.
- Frozen product release and testing environment.
- Predefined tasks: identify an evidence boundary, change a declared assumption, interpret lower/central/upper results, export a RiskPack, and locate a verification failure.
- Success criteria, time limit, assistance rule, severity scale, and stopping rule fixed before sessions.

## Session record

For every participant, retain anonymized task completion, time on task, wrong turns, assistance, errors, abandonment, comprehension checks, and open comments. Do not drop failed sessions or only quote favorable feedback.

## Report

Publish participant count and criteria, task-level completion rates, median and range of completion time, critical-error rate, boundary-comprehension rate, all observed failure modes, withdrawals, missing data, protocol deviations, limitations, and the changes made or deliberately deferred.

The public count changes only after the complete report is stable, permission and privacy requirements are satisfied, failures are included, and the report hash is registered.
